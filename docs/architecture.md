# Architecture and assumptions

A seeded hourly discrete-time engine owns all operational calculations. Freight is represented as aggregate, category-specific lots, with origin and generation hour retained. Every hour executes demand → tenders → responses/pickups → transit → appointments → receiving → staging → processing. Separate inventory states and capacity budgets prevent one department from bypassing another. Each state is JSON serializable, including the random generator state. APIs and the baseline agent use the same validated action model.

FastAPI validates commands; SQLAlchemy stores complete versioned game snapshots in SQLite. A transaction stores each new state. React consumes live observations through a Vite proxy. Zustand keeps client observation and selection; draft decisions are local until preview/commit. React Flow renders the network; Recharts renders actual and forecast series separately. All data and economic assumptions are fictional.

Scope choices: 2,000 synthetic stores are grouped into 35 DC regions for hourly demand and individually inspectable from the map. Trailer loads retain category and origin, with partial final loads allowed. No individual SKU or parcel identities are simulated. Mail-in parcels use carrier capacity in trailer-equivalent lots with extra processing effort. National DC removal pulses occur on configured month days. Department staffing is a daily roster with an effective-hours factor incorporating shifts and breaks. Investments add capacity immediately and have explicit cost. Forecasts are deterministic planning estimates, not simulated actuals. No external AI, paid services, or expensive training.

Initial upstream stock uses synthetic age approximations. This is a teaching simulation, not a calibrated model of any retailer. Hourly transitions are implemented directly; SimPy adds no benefit for this fixed-step model. PostgreSQL can replace SQLite via DATABASE_URL.

Fleet slots are reusable trailer equivalents. A load occupies a slot from tender through yard; unloading releases it. Queue capacity accounting reserves department space once per hour and decrements it per transfer, avoiding quadratic scans as backlog grows. Processing labor score accumulates actual available work budgets across all elapsed hours. The API uses a response schema in addition to request validation. Current API concurrency is serialized with a process-local lock; run a single Uvicorn worker for this local SQLite release.
